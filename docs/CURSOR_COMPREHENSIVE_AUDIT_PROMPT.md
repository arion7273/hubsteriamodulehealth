# Cursor comprehensive audit prompt (any app)

Copy a **filled** prompt from the Module Health UI:

- **Report page** → **Copy comprehensive audit prompt** (includes latest run + app from registry)
- **Or** `POST /api/apps/:appId/comprehensive-audit-prompt` with JSON body:

```json
{
  "environment": "production",
  "targetUrl": "https://your-app.example.com",
  "repoRoot": "/path/on/scanner/checkout",
  "moduleHealthApiBase": "https://your-scanner-or-vercel-ui.example.com"
}
```

Paste the result into Cursor in **the application repo you are shipping** (HubsteriaCare, Guardian, Brew, etc.).

## Module Health API base (web vs local)

| How you use the dashboard | `{API_BASE}` for runs & `GET /api/runs/...` |
|---------------------------|---------------------------------------------|
| `npm run start:prod` locally | `http://localhost:4177` |
| Railway / Render (Docker) | `https://….up.railway.app` (same URL for UI + API) |
| Vercel UI + scanner backend | Vercel site URL if `SCANNER_API_ORIGIN` proxies `/api`, **or** scanner URL if using `VITE_API_BASE` |

Health check: `GET {API_BASE}/api/health` → `{ "ok": true }`.

## Single report analysis (one runId)

On any report page → **Copy report analysis prompt**, or:

`POST /api/runs/{runId}/report-analysis-prompt` with `{ "moduleHealthApiBase": "https://your-ui-or-api-host" }`.

That prompt instructs Cursor to:

1. Fetch `GET {API_BASE}/api/runs/{runId}` (or use embedded JSON)
2. Explain gate, execution counts, and build coverage in plain language
3. List every non-pass finding by severity with fix order
4. Fix plans for blocker/high + one combined implementation prompt
5. Additional Module Health runs to close coverage gaps for a full build gate

Works for **any registered app** and **any host** (localhost, Railway, Vercel with `SCANNER_API_ORIGIN`).

### Paste template (replace `run_XXXXX` and `{API_BASE}`)

```text
I have a Module Health report at {API_BASE}/reports/run_XXXXX.

1. Fetch GET {API_BASE}/api/runs/run_XXXXX (or I will paste the JSON).
2. Explain gate, execution counts, and build coverage in plain language.
3. List every non-pass finding by severity with fix order.
4. For each blocker/high, produce a short fix plan and a single combined Cursor implementation prompt at the end.
5. Say what additional Module Health run (packs/levels/inputMode) is required to close coverage gaps for a full build gate.

Do not invent file paths or test results; use report JSON only.
```

Prefer the **Copy report analysis prompt** button — it embeds the full JSON and app-specific preset links.

## Manual template (fill placeholders)

If you are not using the API button, replace:

- `{{APP_NAME}}` / `{{APP_ID}}` — from Settings or `registry/apps.json`
- `{{ENVIRONMENT}}` — e.g. `production`, `staging`, `local`
- `{{TARGET_URL}}` — live URL for URL preset
- `{{REPO_ROOT}}` — checkout path on the **scan runner** for repository preset
- `{{API_BASE}}` — table above

Then paste the **Part A / Part B / Output format** section from any prompt generated by `buildComprehensiveAuditPrompt` in `engine/comprehensive-audit-prompt.mjs`, or use the report’s **gap analysis** prompt for a single-run deep dive.
